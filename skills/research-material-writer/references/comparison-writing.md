# Comparison and Selection Guide

## Define Comparable Scope

Before research, fix:

- User scenario and constraints.
- Compared versions, plans, or deployment modes.
- Required platforms and integrations.
- Must-have and optional criteria.
- Evidence date.

Do not compare a hosted product with a source library as though they offer the same operational scope.

## Comparison Dimensions

Choose only dimensions that affect the decision, such as:

- Setup difficulty.
- Core capability and extensibility.
- Reliability and observability.
- Security and data boundaries.
- Platform compatibility.
- Maintenance burden.
- Pricing or resource cost.
- Migration and lock-in.
- Suitability for the reader's workflow.

## Evidence Table

Use tables for normalized facts. Place nuance outside the table when a cell would hide important conditions.

Mark values as:

- Verified.
- Vendor claim.
- Inferred.
- Not comparable.
- Unknown.

## Recommendation Logic

Recommend by scenario:

```text
Choose A when ...
Choose B when ...
Avoid both when ...
Run a proof of concept when ...
```

Do not declare an absolute winner unless the user supplied one decisive criterion and the evidence supports it.

## Comparison Failure Patterns

Reject a draft that:

- Uses unequal versions or plans without disclosure.
- Converts missing data into zero or “not supported.”
- Mixes facts and preferences in one score without methodology.
- Uses a feature count as a quality score.
- Hides switching costs or operational burden.
