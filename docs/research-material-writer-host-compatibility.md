# research-material-writer 宿主兼容策略

验证基线：2026-11-03

本文只描述 `research-material-writer`。`workspace-file-maintainer` 已暂停开发，不属于本阶段实现和兼容承诺。

## 目标

首要目标是让个人开发者可以把同一份研究 Skill 核心内容带到不同 Agent 宿主，并针对任意指定项目获得全面、可追溯、边界明确的研究资料。

兼容性声明按“核心格式、发现、显式加载、执行行为、证据可观测性”分层。一个宿主能读取 `SKILL.md`，不等于它已经完成行为兼容。

## Portable Core

核心包只依赖以下语义能力，不依赖具体厂商工具名：

- `source_search`：查找候选权威来源；
- `source_fetch`：读取指定来源或相关章节；
- `provided_material_read`：读取用户明确提供的材料；
- `repository_read`：读取获准的仓库内容；
- `execution_probe`：只有宿主允许且用户明确授权时，执行窄范围验证；
- `user_clarification`：澄清会改变研究范围或证据要求的关键信息；
- `response_delivery`：返回研究结果。

核心不假设网络、浏览器、Shell、文件系统、凭据、MCP、浏览器自动化、沙箱或文件写入。frontmatter 不授予权限；`allowed-tools` 不作为安全边界。

## 综合研究输出

用户要求对任意项目开展系统研究时，核心输出按 `references/project-research-contract.md` 组织，至少覆盖：

- 项目概述与决策摘要；
- 核心功能和能力地图；
- 适用与不适用场景；
- 安装、配置、依赖和权限；
- 基础使用和可观察成功标准；
- 典型工作流；
- 进阶使用；
- 最佳实践；
- 常见问题和排错；
- 限制、风险和未验证项；
- 同类方案比较；
- 综合结论、来源和核验日期。

无法获得证据的章节必须标记为未核验或不适用，并说明影响；不得用合理猜测填充。

## 宿主矩阵

| 宿主 | 适配方式 | 当前等级 | 必须验证 | 降级方案 |
|---|---|---|---|---|
| WorkBuddy/open-spec 基线 | 使用无宿主专有字段的核心包；由宿主提供等价研究工具 | Core format verified；运行行为需按具体构建复测 | 发现、显式选择、来源读取、输出、权限和日期证据 | 让用户提供官方来源或材料；仅输出文档性分析并标记未实测 |
| OpenAI Codex | 安装到宿主支持的 `.agents/skills/` 作用域；使用 `$skill-name` 或 `/skills` 显式选择；使用标准核心包 | Package-compatible；host behavior pending per-version run | `skills list` 可见、显式加载正文、来源能力、输出和执行边界 | 直接把核心提示词和研究契约作为用户提示输入；不宣称 Skill 已加载 |
| 豆包/火山方舟 Skills | 优先使用官方 Skills 上传/引用入口；不假设其支持 `.agents/skills`、Codex 命令、Claude 字段或本地扫描 | Adapter planned / unverified | 官方入口是否接受 `SKILL.md`、版本/来源是否可见、显式引用是否可确认、来源工具和输出是否可观测 | 提供核心 `SKILL.md` 与研究契约文本，由用户在豆包中显式粘贴/引用；使用人工证据记录，标记为 content-assisted research |
| GitHub Copilot VS Code | 独立只读适配器；宿主专用调用和权限说明放在 adapter overlay，不污染核心 | Experimental / evaluation incomplete | 目标目录发现、`/` 菜单显式调用、核心版本、加载证据、工具轨迹和只读边界 | 返回研究结果但标记 Skill 未确认加载；无法取得完整证据时不得升级兼容等级 |
| 其他 Agent | 仅使用标准核心包，新增适配器前先完成 Host Probe | Unverified | 发现路径、刷新机制、显式入口、权限和证据能力 | 复制核心内容作为人工研究提示；不做宿主兼容承诺 |

“Package-compatible”只代表结构上可安装或可被规范校验；“Behavior verified”要求真实宿主、版本、入口、核心哈希、适配器版本、评测集和运行证据全部绑定。

## 宿主能力等级

- **L0 Unsupported**：没有确认的 Skill 接口或无法安全传递研究契约。
- **L1 Content-compatible**：能读取核心 `SKILL.md`，但无法证明发现或加载。
- **L2 Discoverable**：宿主列表或等效接口能显示预期名称、来源和版本。
- **L3 Explicitly loaded**：用户显式选择，且有正文加载或宿主事件证据。
- **L4 Research behavior verified**：核心研究案例通过，来源使用、输出结构、事实分类和降级行为可复核。
- **L5 Boundary verified**：L4 之外，权限、禁止操作、失败处理和证据完整性也通过重复测试。

当前策略：默认对新宿主最高只声明 L1，直到完成 L2-L5 的对应验证。不得将一个宿主的等级外推到另一个宿主。

## 适配器职责

每个宿主适配器只负责：

1. 检测宿主和版本；
2. 把核心包安装到正确的项目/用户作用域；
3. 处理刷新、缓存和同名冲突；
4. 提供宿主的显式调用示例；
5. 把宿主原生工具映射到语义能力；
6. 记录实际 Skill 身份、核心哈希、宿主版本、适配器版本和权限状态；
7. 在能力不足时返回可解释的降级状态。

适配器不得把宿主专有字段写回 Portable Core，也不得用提示词声称拥有宿主没有提供的能力。

## 统一加载判定

一次正式兼容运行至少需要以下证据：

- `ARTIFACT_VALID`：核心包结构、名称、frontmatter 和哈希通过；
- `INSTALLED`：落地路径和作用域可确认；
- `DISCOVERED`：宿主列表显示预期 Skill；
- `SELECTED`：用户显式选择目标 Skill；
- `LOADED`：宿主事件或可追溯正文读取证明加载目标版本；
- `EXECUTED`：运行轨迹证明研究流程实际使用了 Skill；
- `ACCEPTED`：研究输出和边界断言通过。

缺少 `LOADED` 证据时，不能把回答内容判为成功加载。缺少工具输入、来源内容或权限轨迹时，正式结果必须 fail-closed 为 `evaluation_failure` 或 `blocked`。

## 降级和错误处理

| 状态 | 处理 |
|---|---|
| 格式错误 | 阻止安装，指出文件和字段；不自动切换到别的版本 |
| 未发现 | 只执行宿主明确支持的一次刷新；仍失败则停止并报告路径/作用域 |
| 同名冲突 | 展示来源和版本，要求用户选择；不静默覆盖 |
| 不支持显式调用 | 提供宿主无关的研究提示和契约文本，标记为人工调用 |
| 来源工具不可用 | 使用用户材料或输出文档性分析，标记缺失证据和影响 |
| 执行权限不足 | 不自行申请更高权限；把预期结果标为未实测 |
| 加载证据不可观测 | 可以提供非认证性回答，但兼容等级不得超过 L1 |
| 运行中失败 | 保留错误和已验证内容，不把部分结果标记为完整成功 |

重试只允许用于宿主定义的瞬时刷新/网络故障，最多一次；不得重试到不同版本、同名 Skill 或更高权限。

## 发布要求

每个宿主兼容声明必须绑定：

- core Skill 版本和 `SKILL.md` 哈希；
- adapter 版本；
- 宿主产品、表面和版本；
- 评测集版本；
- 验证日期；
- 通过、失败和未观测的能力；
- 已知降级路径。

没有以上信息的宿主只能写“未验证”或“内容格式兼容”。
